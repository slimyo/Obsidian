### 1. Shapelets-Enriched Selective Forecasting using Time Series Foundation Models

**来源**：arXiv 2601.11821，2026年1月

**作者背景**：Shivani Tomar 等四人合作，聚焦 TSFM 在生产环境中的可靠性问题。

**研究动机**： TSFM（如 Chronos、TTM、Moirai、TimesFM）在平均误差指标上表现优异，但论文指出一个关键问题——这些模型在数据出现显著变化或突变模式的局部区段上，预测往往不可靠，而平均误差掩盖了这种局部失效。这直接限制了 TSFM 在真实业务场景中的可用性，尤其是那些包含独特趋势的数据。

**核心方法**： 论文采用"选择性预测"（Selective Forecasting）的经典框架，但创新点在于选择机制的设计——使用 shapelet（时序判别性子序列）作为可靠性判据。具体做法：

1. 在目标域的验证集上用 shift-invariant dictionary learning 学习一组 shapelet（基本模式单元）
2. 计算测试样本与这些 shapelet 之间的距离相似度
3. 距离越远（即该区段的模式与验证集中见过的"安全模式"差异越大），就越不信任 TSFM 在该区段的预测，允许用户选择性丢弃这部分预测

注意：这里的 shapelet 用法不同于经典时序分类中"判别类别"的用法，而是被用来刻画"模型预测可靠的代表性模式"。

**关键发现**：

- 在零样本设置下平均降低 MSE 22.17%，全样本微调设置下降低 22.62%
- 相比随机丢弃策略（random selection baseline），该方法在某些数据集上的提升幅度可达 21%以上
- 证明了"基于输入模式相似度的可靠性判断"是一个有效且轻量的选择性预测信号

**方法局限**：

- shapelet 需要在每个目标域的验证集上重新学习，是 domain-specific 的，迁移成本较高
- 只解决了"trust"这一个维度（是否可信），完全没有涉及"如果不信任 TSFM，该怎么办"（即没有 gain/proposal 维度）
- 没有理论保证（不是 distribution-free 的方法，纯粹经验驱动）

### 2. Bounded-Abstention Multi-horizon Time-series Forecasting

**来源**：arXiv 2602.04714，2026年2月

**研究动机**： 论文指出，"有界弃权"（bounded abstention，也称选择性预测）这一经典机器学习范式，几乎完全被局限在分类和回归任务中研究，而对时序预测这一独特任务形式的弃权机制研究极为有限。已有的少数尝试（如 Hatami & Chira 研究早期时序分类的弃权，Pidan & El-Yaniv 用隐马尔可夫模型研究单步趋势分类的选择性预测）都没有处理"多步预测中该弃权哪些部分"这一更复杂的问题。

**核心方法**： 论文为多步预测场景下的弃权机制提供了严格的理论刻画，形式化为：

$$\arg\min_{(f,g)} \mathbb{E}_{X,Y}[\ell(f(X), Y) \mid g(X)=1] \quad \text{s.t.} \quad \mathbb{E}[g(X)] \geq \phi$$

其中 $f$ 是预测器，$g$ 是选择函数（决定哪些 horizon 步该输出，哪些该弃权），$\phi$ 是覆盖率约束。论文针对三种不同的弃权设定（如逐步弃权 vs. 区段弃权）理论刻画了各自的最优策略形式。

**与已有 UQ 方法的对比**： 论文系统梳理了时序不确定性量化的几条路线——贝叶斯 RNN（需要架构改造和先验假设）、MC Dropout（校准质量差）、分位数 RNN（容易分位数交叉）、Conformal Forecasting RNN（事后方法，有限样本理论保证）——并指出 conformal 方法是当前最灵活、保证最强的路线。

**关键发现**：

- 给出了三种弃权设定下选择函数的理论最优形式（闭式解或可计算近似）
- 证明了"不做任何生成式假设"的情况下也能给出弃权策略的理论刻画，这比依赖隐马尔可夫等生成模型的早期工作更通用

**方法局限**：

- 理论严谨但偏单模型场景：这是"一个预测器 + 一个选择函数"的设定，没有涉及多模型路由
- 没有处理"该选哪个模型"的问题，只处理"该不该输出预测"

### 3. When Routing Collapses: On the Degenerate Convergence of LLM Routers

**来源**：arXiv 2602.03478，2026年2月

**研究动机**： LLM 路由的标准范式是：给定一批候选模型，训练一个轻量路由器来预测每个模型在给定 query 上的表现，再做 cost-aware 的选择，从而在保持质量的同时降低成本。这类方法已经在 RouterBench 等基准上展示了实际收益。但论文发现了一个此前未被充分研究的**系统性失效模式**。

**核心发现——Routing Collapse**： 当用户的预算（cost budget）增加时，现有路由器会**系统性地**倾向于总是选择最强大、最昂贵的模型（如 GPT-4），即使更便宜的模型已经足够完成任务。论文通过在 RouterBench 上的可视化分析展示：随着预算上升，对最强模型的调用率会迅速饱和逼近 100%，路由器实质上退化为"总是选最贵的"这一退化策略，完全丧失了路由本应具备的"按需选择"的价值。

**方法机制分析**： 论文将现有路由方法归为两类——基于启发式信号的方法（如置信度估计、benchmark 衍生规则）和基于学习的方法（将路由形式化为性能预测问题，再做 cost-aware 选择）。两类方法都存在 collapse 现象，说明这不是某个特定算法的 bug，而是路由学习范式本身存在的结构性偏差：当训练信号主要由"准确率提升"驱动时，模型会学到"更强模型几乎总是更准"这一捷径，从而在预算允许时无脑选最强模型。

**关键发现**：

- 这是一个跨方法、跨数据集普遍存在的现象（"previously underexplored failure mode"）
- 揭示了路由学习的一个根本张力：路由器的训练目标（最大化准确率）和路由器的存在价值（节省成本同时维持质量）之间存在隐性冲突，前者会系统性地侵蚀后者

**与你工作的镜像关系（详见联系部分）**： 这篇论文研究的是"过度行动"（over-route to strong model），而你的 F-R9.6（gate collapse）研究的是"过度弃权"（collapse to abstain）。两者方向相反，但本质同构——都是"单一标量信号驱动的路由学习，在某种极端条件下会坍缩为一个退化策略"。

### 4. Conformal Prediction for Time-series Forecasting with Change Points (CPTC)

**来源**：NeurIPS 2025 Poster，arXiv/OpenReview，2025年9月

**研究动机**： Conformal Prediction (CP) 是当前时序不确定性量化的主流框架之一，因其算法简洁、适用性广、具有有限样本覆盖保证而广受关注。但论文指出现有 CP 方法在处理含"变点"（change points，即数据生成过程突然发生切换）的时序时存在明显短板——多数方法假设底层动态稳定，只能适应残差分布的渐进偏移，无法应对生成机制的突变。

**核心方法**： 论文提出 CPTC（Conformal Prediction for Time-series with Change points）算法，核心思路是将一个**状态预测模型**（用于推断当前数据处于哪个底层状态/regime）与**在线 conformal 预测**结合，从而在非平稳时序中更准确地建模不确定性。这是一种"状态感知"的 conformal 扩展，比单纯调整步长的在线 conformal（如 ACI）更细粒度。

**关键发现**：

- 在含变点的合成与真实时序数据上，CPTC 比标准在线 conformal 方法更快适应分布切换后的不确定性水平
- 证明了将"状态识别"显式建模进 conformal 框架是可行且有效的

**与你工作的关系**： 你在 F-R12.5 中用 conformal nonconformity score 作为 trust 信号（避险），这条工作脉络（CPTC 及其引用的 ACI、SPCI 等）提供了这一选择的理论合法性背书——conformal 方法在非平稳时序上经过了专门的研究和验证，不是临时拼凑的工具。同时，CPTC 处理"变点检测+conformal"的思路也可以启发你的 drift_engine 模块——目前你用 5 种 drift 信号做检测，如果能像 CPTC 一样显式建模 regime 状态，可能让 trust 信号在 regime 切换时刻更鲁棒。

### 5. Cascaded LLM Framework with Abstention（van der Schaar Lab, NeurIPS 2025）

**来源**：NeurIPS 2025 Main Track Poster，van der Schaar Lab

**研究动机**： 团队致力于"reality-centric, human-empowering AI"系统的研究方向，即让 AI 系统能够识别自己的能力边界，在恰当的时候升级求助或弃权，而不是盲目自信地给出答案。

**核心方法**： 论文提出一个级联（cascaded）LLM 框架，在三个层级之间自适应地委托任务：

1. 廉价的基础模型（先尝试）
2. 更强大但更昂贵的大模型（必要时升级）
3. 人类专家（最终兜底）

该框架同时优化三个目标的平衡：预测正确性、计算/人力成本、以及"何时弃权升级"的决策本身。一个重要的扩展是引入**在线学习**——利用专家反馈（即人类专家介入后的结果）来持续改进委托决策的策略，形成闭环。

**关键发现**：

- 级联+弃权框架能够在保持高正确率的同时显著降低对昂贵资源（大模型调用、人工介入）的依赖
- 在线学习信号（专家反馈）能够持续提升委托决策的准确性，说明"在线反馈"对这类决策机制有实质性价值

**与你工作的关系**： 这是 LLM 领域的"selective deferral"实践，结构上类似 cascade（依次尝试，逐级升级）而非你的 gate（一次性判断 trust+gain 再决定）。但其中"利用专家反馈做在线学习来增强决策"这一发现，与你在 F-R13.6 中得出的"真正工业杠杆=存在稳定单元+在线反馈"高度印证——这说明跨任务（LLM agent vs. 时序路由）都收敛到同一个结论：离线学习决策机制的天花板有限，在线反馈才是突破口。

### 6. RouterEval / RouterBench / LLMRouterBench 系列

**来源**：RouterBench (Hu et al., 2024)；RouterEval (Huang et al., 2025)；LLMRouterBench (2026年1月)

**研究脉络**： 这是 LLM 路由领域的标准化评测基础设施演进史：

- **RouterBench**（2024）首先建立标准化评测，提供 11 个模型在 7 个核心 NLP benchmark 上超过 40.5 万条预计算输出，使路由算法可以在无需实际推理的情况下被复现比较
- **RouterEval**（2025）大幅扩展规模，覆盖超过 8500 个 LLM 和 2 亿条性能记录，并揭示了一个重要现象：**模型层面的扩展规律**——足够强的路由器在理论上可以超越池中任何单一模型的性能（route 组合的上界高于任何单体）
- **LLMRouterBench**（2026）进一步整合统一协议，支持监督式与启发式路由方法的标准比较，并兼容用户个性化路由（PersonaeRoute-Bench）等新方向

**核心方法范式**： 该领域的路由方法主要分两条线——语义/意图路由（用 query embedding 预测模型适配度，如 RouteLLM 利用人类偏好数据）和性能预测路由（直接学习一个映射，预测每个模型在给定 query 上的表现后再做选择，如 RouterDC 用双重对比学习提升路由准确率）。

**关键发现**： RouterEval 的核心论断——"路由器可以超越任何单体模型"——建立在 LLM 池存在显著互补结构、且这种结构可以从 query 特征中被学出来的前提之上。

**与你工作的关系（核心张力点）**： 这是与你的研究形成**最强对比张力**的一组工作。LLM routing 社区的乐观结论（路由可超越最强单模型）建立在两个假设上：(1) 候选池存在真实的互补结构；(2) 这种结构在 query 层面是可学的。你在时序领域的实证恰恰否定了第二个假设在饱和域下成立——F-R12.1 证明了离线 gain 不可学（AUC 0.47），F-R13.6 证明了即便引入异构专家池制造互补结构，真实数据上 winner 仍从 task-signature 不可预测。这提示一个重要的边界条件：**LLM routing 的成功可能依赖于 LLM 任务空间本身具有比时序更强的、更容易从输入特征中读出的任务-能力对齐结构**，而时序数据的"任务特征"（如你发现的 regime 退化为 ac1/shift/noise 三类）天然更模糊。这个对比本身就是一个值得在论文中明确提出的论点。

### 7. Proactive Routing to Interpretable Surrogates with Distribution-Free Safety Guarantees

**来源**：arXiv 2603.14623，2026年

**研究动机**： 已有的模型级联/路由方法大多是"输出依赖"的——即必须先至少执行一次某个模型，拿到输出后才能判断是否需要路由到另一个模型（如 post-hoc arbiter、output-based selective prediction、guaranteed sequential cascades）。这类方法的问题在于：执行成本无法避免，路由决策本身的"省成本"价值被削弱。

**核心方法**： 论文提出"主动路由"（proactive routing）——将路由形式化为一个**纯输入依赖**的分类任务，在不执行任何候选模型的情况下，仅根据输入特征就决定是否要路由到一个可解释的替代（surrogate）模型。理论基础是 Neyman-Pearson 可行性条件，由此推导出有限样本的安全边界保证。

一个关键的概念区分：论文将"安全约束"定义为**相对于参考模型的退化程度**（substitution quality），而不是预测正确性本身的好坏。这与传统选择性分类（控制条件准确率高于阈值）不同——论文的目标是控制"换了模型后比不换差多少"，而不是控制"换了之后对不对"。

**关键发现**：

- 在不需要执行候选模型的前提下，仍能给出有限样本的安全边界
- 区分了"安全"（不比 base 差太多）和"质量"（绝对正确）两个不同的控制目标

**与你工作的关系**： 这篇论文的"安全约束 vs. 质量目标"的区分，与你的 trust（避险，对应安全约束）vs. gain（获利，对应能不能真的变好）的区分高度同构，可以作为你 F-R12.5 双信号解耦论点的一个理论旁证——独立的两组研究者从不同角度（一个是纯理论的 proactive routing，一个是你的实证驱动）都得出了"安全"和"质量/收益"应当被分开建模的结论。但论文没有像你一样实证证明"获利信号离线不可学"这一更强的负面结果，你的工作在这一点上提供了他们理论框架下尚未被验证的实证反例（即在你的设定下，即便框架正确，gain 子任务的可学性仍然为零）。

### 8. Spectral Predictability as a Fast Reliability Indicator for Time Series Forecasting Model Selection

**来源**：arXiv 2511.08884，2025年11月

**研究动机**： 论文指出已有的时序模型选择方法存在效率与可解释性的两难：谱熵（spectral entropy）等快速指标速度快但不提供模型指导；验证子集方法（在小验证集上试跑候选模型）速度中等但不可解释；元学习和 AutoML 方法效果好但计算开销巨大。论文试图找到"快、可解释、且能提供模型选择指导"三者兼顾的方案。

**核心方法**： 提出"谱可预测性"（Spectral Predictability，记作 Ω）指标，纯粹基于数据本身的频域特性计算，不需要训练或运行任何候选模型，作为一个**快速预筛选器**，帮助实践者将昂贵的验证资源聚焦到一个更小的、更有希望的候选子集上。

**关键发现**：

- Ω 指标计算速度快（接近谱熵和近似熵的量级）
- 同时具备模型指导能力（不同于纯熵指标）和可解释性（不同于元学习黑盒）
- 定位为现有方法的**互补**而非替代——快速过滤后仍需结合更精细的方法做最终选择

**与你工作的关系**： 这是你的 saturation detector（M12，预测 oracle gap）的一个"数据侧"对应版本。你的方法是从模型表现历史中学习 gap 回归器（corr 0.37），而这篇论文是从数据本身的频域特征直接计算一个免训练指标。两者可以视为互补信号——如果将 Ω 指标加入你的 saturation/gain 特征工程中，可能为"为什么某些 cell 的 gain 不可学"提供额外的数据侧解释维度：也许 gain 不可学的 cell 恰好是谱可预测性低的 cell（信号本身就缺乏可被任何模型稳定捕捉的结构），这能把你的负面结果往前推进一步，从"不可学"细化为"在什么条件下不可学"。

### 9. Efficient Model Selection for Time Series Forecasting via LLMs

**来源**：arXiv 2504.02119，2025年

**研究动机**： 论文指出传统时序模型选择高度依赖领域专家的经验和大量计算资源（穷举式评估候选模型不现实）。已有元学习方法（如基于时序元特征训练性能预测器）已被证明有效，但论文进一步探索：能否用 LLM 本身作为这个元学习器？

**核心方法**： 利用 LLM 的零样本推理能力，直接将数据集描述和候选方法描述输入 LLM，让其基于这些描述（而非真正训练任何模型）来预测/排序哪个方法更适合当前数据集，替代传统需要训练专门元模型的流程。

**关键发现**： 论文证明这种"LLM 作零样本元选择器"的方式在效率上有明显优势（不需要训练元模型，不需要预先在大量历史数据集上跑候选方法收集元特征），但其选择准确率与专门训练的元学习方法相比存在差距,需要在效率和准确率之间权衡。

**与你工作的关系**： 直接对应你 Round 12 的 E7（Proposal Net 实验）——你发现轻量级 proposal-net 在效果上已经能逼近 LLM（profit 0.235 vs 0.267），说明"用 LLM 做 proposal"这件事的边际价值有限，可以用更轻量的网络替代,这与本文"LLM 元选择器准确率不及专门训练模型"的发现方向一致,但角度不同——本文是从"用 LLM 替代训练"的效率视角论证,你是从"轻量网络替代 LLM"的成本视角论证,两者殊途同归地指向同一个结论:在 proposal 这一子问题上,API 驱动的 LLM 不是必需品。

### 10. OOD-Chameleon: Is Algorithm Selection for OOD Generalization Learnable? (ICML 2025)

**来源**：ICML 2025 Poster，arXiv 2410.02735

**研究动机**： 分布外泛化（OOD generalization）面临的核心难题之一是：分布偏移的形式多种多样（协变量偏移、标签偏移、虚假关联组合偏移等），已有大量算法各自针对特定偏移类型有效，但**为给定数据集选择正确的算法**这件事本身缺乏系统方法，往往依赖专家试错。论文提出一个根本性问题——这种算法选择本身是否可学？

**核心方法**： 将算法选择形式化为一个**多标签分类**问题：在一个由"数据集的数据集"（dataset of datasets，即跨越多种不同分布偏移类型和强度的合成/真实数据集集合）上训练一个选择器（OOD-Chameleon），让其学习从**数据集特征**（不需要先训练任何模型）直接预测候选算法（GroupDRO、过采样、欠采样、logit 调整等）中哪个最适合当前数据集。

**关键发现（正面结果，与你形成关键对比）**：

- OOD-Chameleon 能够在**未见过的**分布偏移类型和数据集上，仅凭数据集特征排序出合理的候选算法，取得显著低于任何静态算法选择的测试误差
- 论文进一步验证了选择器学到的并非简单的查表或线性关系，而是数据集特征与算法表现之间**非平凡的、非线性的**关系
- 论文明确将这一结果定位为对"算法选择是否可学"这一元问题的**肯定回答**（proof of concept）

**与你工作的关系（核心张力点，强烈建议在论文中讨论）**： 这是与你的研究形成**最直接、最值得深入讨论的对比**。OOD-Chameleon 在 OOD 泛化算法选择这一问题上得到了正面结果（可学），而你在时序模型路由的 winner 预测问题上（无论是 Round 9 的 learned belief、Round 10 的 saturation detector,还是 Round 13 的异构专家池）反复得到负面或部分负面的结果（真实数据上 −0.62pp 到 −6.37pp 不等）。

这个对比提出一个值得深挖的问题：**为什么"算法选择"在 OOD 泛化领域可学,而"模型选择"在时序路由领域不可学(或仅在合成数据上可学)?** 可能的解释方向：

1. **任务空间结构性差异**：OOD-Chameleon 的"数据集特征"主要来自分布偏移的可解析维度（偏移类型、强度等,这些维度由实验设计者在合成时显式控制并标注),其训练分布天然与可学的标签结构对齐;而你在 Round 13 发现真实时序数据的"regime"会塌缩成 ac1/shift/noise 三类粗粒度特征,缺乏类似 OOD 偏移那样可被清晰参数化的中间表示
2. **数据集规模与多样性**：OOD-Chameleon 用于训练的"数据集的数据集"规模和多样性可能远超你在 38 个 UCR/UEA 数据集上能达到的规模,样本量不足可能是你 winner 预测 LODO acc 仅 0.113-0.249 且"特征越丰富越差"(过拟合)的部分原因
3. **任务难度的本质差异**：也可能是时序路由问题本身的标签噪声(few-shot 场景下,哪个模型"赢"在统计意义上可能本就不稳定)远高于 OOD 算法选择问题

将这一对比写入论文,可以把你的负面结果从"我们的实验没做好"提升为"在两个不同但结构相似的元学习问题上,可学性出现本质性的领域差异",这是一个更有理论深度、也更容易让 reviewer 认可价值的论述框架。

### 11. AgentOpt / Router-R1 及多步路由优化视角

**来源**：AgentOpt v0.1 Technical Report，arXiv 2604.06296

**研究动机**： 论文观察到现有 LLM 路由方法的一个共性局限——绝大多数路由方法的"优化单元"是**单次查询**（per-query, per-call）：给定一个输入，选一个最佳模型。但很多实际场景下,真正需要优化的是**完整的流水线轨迹**(full pipeline trajectory),而不是孤立的单步决策。

**核心方法**： 论文提及的 Router-R1（Zhang et al., 2025）将多 LLM 路由形式化为一个**序贯决策过程**,用强化学习训练路由器,使其能够交替进行"推理"和"动态调用模型"两个动作,并在多轮调用后聚合各模型的响应——这是对传统单轮、一对一路由的重要扩展。但论文也指出 Router-R1 仍然停留在单条 query 级别的路由,尚未真正做到"优化整条流水线轨迹"。

**关键发现**：

- 序贯路由相比单次路由能捕捉到更丰富的决策结构(如"先问哪个模型,再问哪个模型,如何融合"这类多步策略)
- 但"优化单元"从单次查询提升到完整轨迹仍是一个尚未被充分解决的开放问题

**与你工作的关系**： 你的 Round 6 自适应运行时(adaptive_decide → scheduler → safe_predict → ensemble → action_layer → adaptive_observe)本质上已经是一个**闭环轨迹级**的决策系统,而非单次路由——这比当前 LLM routing 主流方法(单次查询路由)和 Router-R1(序贯但仍是 query 级别)在结构上更进一步,因为你的系统包含了显式的 drift 检测、动作干预(MONITOR/INSPECT/THROTTLE/SHUTDOWN/ESCALATE)和持续反馈闭环。这提示你在论文定位时可以强调:**你的 adaptive runtime 设计本身在"路由优化单元"这一维度上,已经超越了当前 LLM routing 文献正在探索的前沿(轨迹级优化)**,只是你诚实地报告了 F-R15 这一负面结果(adaptive 是高方差全或无策略)。这并不削弱贡献——恰恰相反,这说明"轨迹级闭环路由"这条路线本身存在尚未被充分理解的高方差陷阱,而这正是 LLM routing 社区(包括 AgentOpt/Router-R1)尚未触及的下一个问题。
